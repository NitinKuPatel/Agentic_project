## 0. Executive Summary

This document defines the **enterprise-grade architecture** for the Agentic AI KB Bot.  
It ensures:

- Accurate, KB-grounded answers  
- Role-based access control (RBAC)  
- Auditability & reproducibility  
- Deterministic fallback in failures  
- Cost and SLA control  
- Full lineage of documents and answers  

> This is not a general chatbot; it is a **controlled, agentic AI system**.

---

## 1. Core Design Principles

1. Truth comes from documents, not the model.  
2. Every answer must be traceable and reproducible.  
3. Every answer must be authorized based on user role.  
4. Failures must be safe and explicit.  
5. Ambiguity must be classified, not guessed.  
6. Cost and usage must be bounded.  
7. The system must degrade gracefully if LLM or retrieval fails.

## 3. Detailed Agentic Pipeline

1. **Query Intake**
   - Normalize & hash query
   - Assign unique `query_id`
2. **Authorization & RBAC**
   - Resolve user roles
   - Enforce document-level ACLs
3. **Ambiguity Classification**
   - Document-scope ambiguity → forced clarification
   - Semantic ambiguity → optional clarification
4. **KB Snapshot Binding**
   - Bind query to immutable `kb_snapshot_id` and `active_doc_set_id`
5. **Hybrid Retrieval**
   - Vector search (FAISS / Milvus)
   - BM25 keyword search
   - ACL filtering applied before retrieval
6. **Context Controller**
   - Validate similarity threshold
   - Deduplicate chunks
   - Token budget enforcement
7. **Response Generation**
   - LLM synthesis if available
   - Fallback mode: top chunks verbatim
8. **Response Validation**
   - Source citations
   - Confidence band assignment
9. **Audit Logging**
   - Full trace of query → retrieval → response
   - Snapshot and chunk IDs recorded
10. **Human-in-the-loop Escalation**
    - Triggered on low confidence, conflict, or sensitive query

## 6. Async & Performance Considerations

* Fully async: FastAPI + Motor (MongoDB async client)
* Circuit breakers on:

  * LLM API
  * Vector DB
* Parallel retrieval for BM25 + vector search
* Redis cache for frequent queries and snapshot metadata

---

## 7. Security & Compliance

* Role-based access enforced before retrieval
* MongoDB stores **full audit + lineage**
* All fallback and LLM responses logged
* Immutable snapshots for reproducibility
* Sensitive queries → human-in-the-loop

---

## 8. Usage Governance

* Rate limiting by user / role / tenant
* Query deduplication by semantic similarity
* Cost budgets per tenant
* Automatic fallback to keyword-only mode if cost or latency thresholds exceeded

---

## 9. Deployment Recommendations

* Containerized using Docker
* Orchestrator + FastAPI behind Nginx / API Gateway
* MongoDB replica set for HA
* FAISS / Vector DB separate cluster
* Redis for cache / rate-limits
* Observability: Prometheus + Grafana + ELK stack

---

## 10. Agentic Characteristics

1. **Plans:** Selects retrieval, fallback, and LLM paths
2. **Executes:** Retrieves docs, prepares context, generates answers
3. **Critiques:** Validates answers, enforces RBAC, logs for audit
4. **Recovers:** Automatically falls back to deterministic mode
5. **Replays:** Supports full historical reproduction of answers

---

## 11. Audit & Compliance Readiness

* Query bound to snapshot and document versions
* Full lineage metadata stored
* Immutable audit logs
* Human-in-the-loop escalation for sensitive queries
* All operations replayable offline
